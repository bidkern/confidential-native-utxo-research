# Adversarial review

This is self-review of a research prototype, not an independent audit.

The findings below describe the initial standalone prototype. The subsequent Core lab exercises native chain selection, undo, persistence and chainstate rebuild; its security boundary and remaining limitations are documented in [CORE_INTEGRATION.md](CORE_INTEGRATION.md). Those integration tests do not constitute a cryptographic audit or comprehensive crash-recovery testing.

## Issues found and addressed

1. **Supply requirement conflict:** resolved explicitly with the user. Conditional binding/proof soundness replaces plaintext sum audit; public coinbase alone does not prevent hidden inflation after a cryptographic break.
2. **Wrong amount upper bound:** a single broad bit-range proof does not enforce MAX_MONEY. Two 52-bit proofs plus complement tally enforce the exact interval.
3. **Blinding imbalance:** independent random blinds require an excess proof or adaptive final blind. Implemented a library exact-zero proof and tally; an arbitrary public residual point without proof would be inflationary.
4. **Cipher nonce reuse across replacements:** selected AES-GCM-SIV before coding rather than deriving a repeated ChaCha20-Poly1305 nonce for changed plaintext.
5. **Dependency overflow:** secp256k1-zkp 0.11.0's range wrapper computes `max_value+1`. A valid 64-bit proof can overflow that expression. Enforce the exact 52-bit header/length (or exact-zero form) before library verification; regression test uses a real generated 64-bit proof and expects rejection in both profiles. No dependency files were patched.
6. **Point-encoding confusion:** Pedersen commitment bytes are not ordinary SEC1 keys. Use library tally and zero-value proof rather than changing a commitment prefix to obtain a signing key.
7. **In-block undo:** naÃ¯vely restoring every spent input resurrects intermediate outputs. Undo records only spends present before the block, then removes all creations. A parent/child spend in one block is covered by tests.
8. **Atomicity:** transactions and blocks validate against a staged map. Invalid later transactions and overpaid coinbase must leave tip and coins untouched.

## Attack coverage and remaining risk

| Attack | Defense / evidence | Remaining limitation |
|---|---|---|
| 10->11 BTC inflation | Validly signed/proven outputs fail conservation tally | Assumes binding and backend soundness |
| Negative or oversized value | Fixed ranges, complement relation, transparent bounds | Independent formal/cross-platform analysis pending |
| Cancellation via invented excess | Exact-zero proof binds E to zero value | Cryptographic composition review pending |
| Point/proof malformation | Fixed point sizes, library parser, canonical proof headers | FFI fuzzing/sanitizers not run |
| Duplicate and replayed inputs | Explicit UTXO consumption, duplicate rejection | No network mempool implementation |
| Ownership substitution | BIP340 signatures bind complete base body and prior outputs | Only key-spend semantics modeled |
| Malleability | txid excludes proof/signature witness; block model binds wtxid | Witness bytes can change wtxid; not Bitcoin block serialization |
| Proof-verification DoS | Bounded counts, bytes and fixed proof lengths | Current costs high; production budget/cache missing |
| Scan DoS | Bounded outputs and accounts; match keys before AEAD; bad metadata doesn't abort other matches | Full-chain cost scales with accounts; no compact filter/index protocol |
| Reused receiving material | Input-bound context and output index | Conflicting replacements reuse context; wallet RNG failure remains serious |
| Address/account linkage | Independent hardened keys; no common scan key/fingerprint | External identity, timing and endpoint leakage persist |
| Recovery loss | Public encrypted openings, full chain replay, explicit account range | Sparse account discovery and invalid sender metadata can lose discoverability |
| Reorg inconsistency | Native undo, replay canonical branch for wallet | Persistent crash recovery and chain selection absent |
| Fee/change/input clustering | No cryptographic fix claimed | Visible graph deliberately accepted |
| Public boundary correlations | Explicit threat model and single-output inference | Confidentiality cannot reverse disclosure |

## Production blockers

- The selected proofs are large and slow relative to transparent transfers; no mainnet viability claim.
- The prototype has not been audited. Frozen vectors are regression fixtures generated by this implementation, not independent confirmation.
- No general Taproot script paths, relative locks, PSBT, mempool packages, PoW, database crash consistency, full block wire decoder, or Core integration.
- Scalar and secret buffers are not comprehensively zeroized; no hardware-wallet or side-channel validation. Tests intentionally use public deterministic seeds.
- The simulator clones its map when staging blocks and recreates cryptographic contexts frequently. Performance numbers include these choices, not optimized Core behavior.
- A proof-system failure could destroy supply integrity without a public plaintext audit catching the discrepancy. Public issuance remains inspectable but is not a substitute.

Do not use test keys, addresses or code to custody real funds. No mainnet submission facility exists.
